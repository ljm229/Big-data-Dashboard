# 架构与运行边界

## 唯一生产链路

```text
翱象 / 淘宝闪购后台
  → automation（导出、粒度校验、幂等入库）
  → MySQL dashboard
  → sync-db-to-json.mjs
  → web/src/data/*.json
  → GitHub Pages / Vercel 静态前端
```

`automation/.env` 是抓取与 MySQL 的唯一连接配置位置。每日运行
`automation/scripts/daily-run.ps1`；白天仅刷新经营数据时运行
`automation/scripts/midday-refresh.ps1`。前端构建命令为
`npm --prefix web run build`。

## 服务边界

| 组件 | 状态 | 职责 |
| --- | --- | --- |
| `automation/` | 生产 | 采集、文件归档、MySQL upsert、水位更新、JSON 生成 |
| `database/mysql-schema.sql` | 生产 | MySQL `dashboard` 的完整新环境建表基线 |
| `server/mysql-api.mjs` | 本机/内网可选 | 为运营质量和经营明细提供 `/api`；`npm start` 启动 |
| `web/` | 生产 | 静态前端；绝大多数页面读取版本化 JSON 快照 |
| `assets/templates/` | 辅助 | 人工上传页面使用的 Excel 模板；不参与每日抓取 |
| `archive/` | 本机归档 | PostgreSQL 原型、旧同步脚本、旧原型和测试报告；不参与构建、部署或日更 |

## 数据粒度约束

- 日表：流量、商品门店、经营、利润、订单毛利、运营质量，按其各自事实键 upsert。
- 周期表：`fact_product_item_period`。平台导出的商品明细是周期汇总，**不得**用于日趋势或补造日期。
- `refresh_state` 的 `latest_biz_date` 和 `row_count` 是链路验收水位；必须同时与事实表实数对账。
- 空值不当作 0；比率聚合按分子/分母或业务权重计算，不平均百分比。

## 运行约束

- 静态部署不会携带本机 MySQL API；需要数据库实时功能时，通过内网部署 API 并配置 `VITE_API_BASE`。
- 新环境先执行 `database/mysql-schema.sql`，再运行导入；禁止执行 PostgreSQL 初始化脚本替代它。
- 不在日更中写回原始 Excel；`automation/output/` 是原始凭证归档。
