# 经营异常 TOP5

实施日期：2026-09-15。范围仅为经营总览右上异常模块，不改其他模块的 KPI、布局或地图城市选择行为。

## 展示与交互

- 延用现有 Vue、字体和蓝色大屏色板，不引入第二套组件库。采用“汇总 → 两行紧凑清单 → 详情”的分层布局；清单从顶部排列，不因记录少而拉高单行。
- 汇总为营业门店异常店数（门店去重）、重点异常项数、关注异常项数。一个门店可有多个平台或规则异常，项数不等于店数。
- 局部分类：全部 / 利润 / 供给 / 服务；不改变大屏全局城市、平台、门店，汇总数不随局部分类改变。
- 营业门店与“筹备 / 待核对”分开。后者不计入营业异常汇总。
- 最多显示 5 项，面板高度不足时可滚动；更多记录可点击“全部 N 项”打开完整清单。
- 点击行只开详情；再点“在大屏查看此门店”，才设置全局平台和门店并触发地图定位。城市单独筛选仍为城市汇总。
- 详情含指标对应日、命中天数、有值天数、真实金额/数量、逐日趋势、同日运营考核、建议和原文件行号。原生 dialog 处理焦点约束，Escape 关闭，关闭后恢复焦点。
- 不显示“今日”、实时告警、持续时长、处理状态、责任人或无依据的预估损失总额。所有日期为业务数据日，不是导入时间。

## 三类判断规则

| 分类 | 触发 | 聚合与排序 |
| --- | --- | --- |
| 利润 | 单日预计毛利（含平台后返）< 0 元 | 重点；同门店×平台合并，展示最低日毛利及负毛利日数 |
| 服务 | 单日源退款率 ≥ 5% | 关注；展示最高单日退款率及命中日数；不重算未知分母 |
| 供给 | 淘宝闪购单日商品出勤率 < 85% | 关注；展示最低单日出勤率、同日缺货/缺勤商品数 |

5% 和 85% 沿用项目已有配置，**未宣称是官方考核标准，待业务确认**。配置入口为 `web/src/utils/riskAnalysis.ts` 的 `RISK_RULES`。

排序为负毛利 → 退款 → 供给。同类按异常程度、命中天数、对应日和稳定标识排序，不将金额、比率、订单量混作一个影响分数。

日模式的趋势额外展示前 6 日，只作对照，不计入当前日命中数。周/月模式逐日判断后合并；即使周期毛利合计为正，也不掩盖单日负毛利。不同日期的商品数不相加、不假称去重 SKU。条长表示指标绝对幅度，数值保留正负号。

退款金额是退款，不等同于经营损失。缺勤损失只显示源表当日估算（含真实 0），缺失显示“—”。未知率或超出 0～1 的率不判正常。缺数据日不填 0，不回退到历史异常假装是所选日期。

## 数据与限制

独立读取“数据源1”中的四张表，原 Excel 只读：

1. 城市门店及上线进度：32 店；状态是当前快照，不能证明某历史日是否营业。待营业和未匹配门店归入待核对。
2. 渠道门店周期数据近30日：1,009 条。毛利、源退款率、退款金额/订单、负毛利订单等。
3. 商品分析按店铺汇总：573 条，仅淘宝闪购。选择美团、京东或 POS 时，供给明确标为不适用。
4. 门店营运考核指标：408 条有效记录；跳过 66 行重复表头/无指标行。售罄率、错漏拣率、仓T、IM 回复率、商责问题订单率、店铺分只在详情中作同日门店级参考，不冒充平台拆分指标。仓T 单位未核实，标“源值”。

本次数据最新日为 2026-09-13。每日表按日期×门店×平台（供给/考核无平台）唯一键校验；重复同值去重，重复冲突报错并保留上一份输出。文件缺失、列名变化、空源也报错，不静默覆盖成空数据。

“规则与覆盖”列出当前筛选下各分类有值的营业门店数与最新日期。有值覆盖只代表期内至少一天存在该指标，不代表每天/每平台完整。9 月 13 日利润、退款覆盖 18/19 个营业门店，供给覆盖 19/19。

商品明细周报、逆向订单、配送异常单没有纳入本版排名。它们需要先处理周期差异、订单去重和异常订单分母，再扩展规则。运营考核阈值未确认前，不推断“不达标”。

## 文件职责与刷新

| 路径 | 职责 |
| --- | --- |
| `scripts/sync-risk-data.py`、`.mjs` | 本地 Excel 校验、标准化、快照生成；不联网、不采集、不操作数据库 |
| `web/src/data/riskData.json` | 派生快照，记录文件路径、表名、SHA256、原始行号及导入时间 |
| `web/src/utils/riskAnalysis.ts` | 可独立测试的规则、期间合并、覆盖计算 |
| `web/src/api/riskSummary.ts` | 前端数据适配，隔离其他模块的指标口径 |
| `web/src/components/boards/RiskTop.vue`、`risk-top.scss` | 面板、清单、详情与交互 |
| `web/scripts/risk-analysis.test.mjs` | 规则、数据一致性及导航回归测试 |
| `web/scripts/risk-browser-qa.mjs` | 独立无头浏览器排版、焦点与交互检查 |

更新本模块：在 `web` 目录运行 `npm run data:sync-risk`，随后 `npm run test:risk`、`npm run build`。开发预览会热更新；生产环境需发布新构建。此命令只更新本模块快照，不重写其他模块数据。

运行要求：Python 3 + openpyxl。包装命令优先使用 `RISK_PYTHON` 环境变量，其次本机已有的 bundled Python，最后系统 Python；不自动安装软件。生成新业务数据仍需更新原始 Excel，刷新网页不等于抓取。此版没有增加定时任务或恢复之前删除的采集程序。
